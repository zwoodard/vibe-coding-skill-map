Context Window Management

Budget your tokens wisely and keep conversations efficient

What is a Context Window?

A context window is the maximum amount of text (measured in tokens) that an LLM can process in a single request. This includes everything: your system prompt, the files you share, your messages, and the AI's response. If you exceed the window, you hit a hard limit and can't proceed.

Tokens are the smallest units of text—roughly one token per word, though special characters and whitespace matter too. A typical context window is 100K-200K tokens. That sounds big until you load a large codebase or a long conversation history.

Why Context Window Matters

A larger context window lets you share more code, more conversation history, and more examples with the AI. This improves accuracy—the AI understands your codebase better with more examples and context.

But larger context has costs: slower processing, higher API bills, and diminishing returns. The "lost in the middle" effect means LLMs attend more to the beginning and end of context, struggling to retrieve information from the middle. Budget wisely.

Token Budgeting Strategies

  • System Prompt: Keep it under 1K tokens. You're paying for this with every request.
  • Code Context: Share only relevant files, not your entire codebase. A focused 10K-token context beats a bloated 50K one.
  • Conversation History: Old messages add up. After 20-30 exchanges, consider summarizing or starting fresh.
  • Examples: A good example (100-200 tokens) teaches faster than vague instructions (1000 tokens).
  • File References: If you can't share the full file, paste the relevant function or class (50-200 tokens) instead of everything.

Prompt caching can cut context costs by 90% if you're reusing the same system prompt or project context across requests.

When to Start a Fresh Conversation

Continuing a conversation is efficient if the context is still relevant. But if you've solved the original task and moved to something unrelated, start fresh. Carry-over context from a completed feature wastes tokens on irrelevant information.

Signs it's time to start fresh: (1) The conversation is 30+ exchanges, (2) You've moved to a completely different feature, (3) The AI is struggling to stay focused.

Summarization Tactics

If a conversation has been long and productive, summarize the decisions made before starting a new conversation. Keep a quick summary in a file or doc: "We decided to use JWT for auth, simplified the API routes, and settled on React Query for state management."

This summary lets you brief the AI on prior decisions without hauling your entire conversation history into the next session.

Using File References to Save Tokens

Most AI tools let you reference files without pasting their full content. In Claude Code, you can say "Look at src/auth.ts" and Claude reads it without you pasting 500 tokens of code.

Use references whenever possible. Only paste code snippets when you need the AI to focus on specific lines or patterns.

Retrieval-Augmented Generation (RAG)

For large codebases, RAG (vector search over your docs) retrieves only relevant sections. Instead of loading your entire codebase into context, you search for relevant functions, configs, or patterns—bringing in 2-3K tokens of context instead of 50K.

For most teams, a simple Markdown knowledge base (organized and searchable) beats complex RAG. But if your codebase is massive, RAG becomes essential.

Practical Token Budgets

Small feature (CRUD endpoint): 20-30K tokens total. System prompt (1K) + codebase context (5-8K) + conversation (10-15K) + response (3-5K).

Medium refactor (module restructure): 60-80K tokens. More context needed, longer planning.

Large project (architectural change): 100-150K tokens. Multiple files, deeper context, more back-and-forth.

These are ballpark figures. Monitor your actual usage and adjust.
