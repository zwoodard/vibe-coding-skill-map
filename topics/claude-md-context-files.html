CLAUDE.md & Context Files

Persistent project context for AI agents that stays loaded across conversations

What is CLAUDE.md?

CLAUDE.md is a special Markdown file that lives in your repository root and provides Claude (and compatible AI tools) with permanent project context. Every conversation starts with this file already loaded, eliminating the need to re-explain your tech stack, coding conventions, or gotchas repeatedly.

It's a configuration file for your AI assistant—like a .gitignore but for context. Claude reads it automatically and incorporates the instructions into every session.

What to Include in CLAUDE.md

  • Project Overview: One-liner description. "Next.js e-commerce app with Stripe and PostgreSQL" tells Claude more than rambling prose.
  • Tech Stack: Framework versions, databases, key libraries. Precision matters—"React 18.2 with TypeScript 5.0" is better than "React with TS."
  • Code Style: Formatting preferences, naming conventions, patterns you enforce. Link to existing examples in your codebase.
  • Project Structure: Directory layout. Help Claude understand where things live.
  • Commands: How to run tests, build, lint, deploy. Use exact commands you'd type in terminal.
  • Gotchas & Warnings: Project-specific quirks. The authentication module with weird retry logic. The API endpoint needing a custom header. These are gold for AI accuracy.
  • Common Patterns: Idioms your codebase uses. Error handling approach, logging strategy, validation patterns.

CLAUDE.md Example

# Project: Payment Dashboard
Next.js 15 app with Stripe integration and PostgreSQL.

## Tech Stack
- Next.js 15 (App Router)
- TypeScript 5.3
- PostgreSQL 16
- Stripe API v2024-01

## Code Style
- Use const for all variables
- Functional components only
- Error boundaries for async UI

## Commands
- Test: `npm run test`
- Build: `npm run build`
- Dev: `npm run dev`

## Gotchas
- Stripe webhooks require env var STRIPE_WEBHOOK_SECRET
- Database migrations must be reversible

Keep CLAUDE.md under 200 lines. Longer files consume more context and reduce adherence. Concise beats comprehensive.

Similar Files: .cursorrules, AGENTS.md

.cursor/rules/: For Cursor IDE. As of 2025, Cursor migrated from a single .cursorrules file to a .cursor/rules/ directory containing individual rule files. Similar purpose to CLAUDE.md but Cursor-specific.

AGENTS.md: An emerging standard launched by Google, OpenAI, Factory, and others in late 2025. Vendor-neutral format for agent instructions. Use this for cross-tool compatibility.

Create all three if you're using multiple AI tools. They're lightweight and reinforce the same principles.

Where to Place Context Files

  • Project root: For team-wide conventions (recommended)
  • Subdirectories: For module-specific context (e.g., src/api/CLAUDE.md for API-specific rules)
  • Home directory: For personal/universal preferences that apply to all projects

Claude searches up the directory tree for these files, so placing one in a parent directory applies to all child projects.

The /init Command

Many AI tools offer a command to auto-generate CLAUDE.md by analyzing your codebase. In Claude Code, use /init to scan your project structure, package files, existing docs, and code patterns, then generate a starter CLAUDE.md tailored to your project.

The auto-generated version is a great starting point—refine it with your specific gotchas and conventions, then commit it to Git.

Best Practices

Write CLAUDE.md like documentation both humans and AI need to understand quickly. Use headers and bullets liberally. Specific, concise instructions beat vague guidance. Don't repeat what's already in your code or documentation—link to those instead.

Update CLAUDE.md as your conventions evolve. It's not a one-time setup—it's a living document that grows with your project.
