Phase 6 — Sub-Agents & Orchestration

Claude Agent SDK

Build production agents with orchestration, memory, tools, and multi-agent coordination built in.

What Is the Claude Agent SDK?

The Claude Agent SDK is Anthropic's framework for building autonomous agents that manage their own tool execution, context, and reasoning loops. Unlike the base Claude API (where you manage tool calls manually), the SDK handles the agent loop for you: it runs the model, interprets tool calls, executes tools, feeds results back, and continues until the task is complete.

The SDK includes 14+ built-in tools (Read, Write, Bash, Glob, Grep, WebSearch, WebFetch), memory management, support for multi-agent coordination, and MCP server integration. It abstracts away boilerplate so you focus on defining agent behavior and capabilities.

Core Features & Setup

To build an agent, you define: an agent type with a unique name and role description, the system prompt (instructions for the agent's behavior), available tools (subset of built-ins or custom), and optionally a different Claude model. The SDK then manages the execution loop—you provide a task, the agent runs until completion, and you get results.

Setup: install the SDK via npm or pip, authenticate with your Anthropic API key, import agent utilities, define your agent configuration, and call the agent with a task. The SDK handles context management, automatic re-reading of CLAUDE.md files when context is compacted, and graceful error recovery.

Tool Management & MCP Integration

The SDK provides built-in tools like read (read files), write (create/edit files), bash (execute shell commands), grep (search files), glob (find files by pattern), and web tools. You can restrict which tools each agent sees—a reviewer agent might not need write/bash, only read and grep.

For external tools, connect MCP servers via stdio or HTTP. Tools from MCP servers follow the naming pattern mcp__<server-name>__<tool-name>. The SDK supports lazy loading: tools are fetched on-demand rather than loaded upfront, saving context window space.

Subagent & Team Architecture

Define multiple agent types and orchestrate them as a team. One session acts as the lead, coordinating work and assigning tasks to teammates. Each teammate gets its own isolated context window. By default, subagents can communicate directly with each other, sharing results without re-routing through the lead.

This architecture enables parallelization: spin up multiple agents to work on independent tasks simultaneously. It also manages context bloat: instead of a single agent carrying a 100k token context, distribute work across 5 agents with 20k each. Only relevant results bubble up to the coordinator.

Memory & Context Persistence

The SDK manages short-term memory (current conversation history) and long-term memory via the memory tool. Agents can create, read, and update memory files that persist across sessions. This lets agents learn from past interactions: "Last time we debugged this, the issue was in database connection pooling."

When context approaches limits, the SDK automatically compacts conversation history, re-reads CLAUDE.md files, and continues. This keeps agents functional even on long-running tasks.

When to Use SDK vs. Raw API

Use the Agent SDK if: You want the agent loop managed automatically, you need multi-agent coordination, you want built-in memory and tool management, you're building production systems that need reliability. Use the raw Claude API if: You're building a chatbot (simple turn-by-turn interaction), you need maximum control over the agentic loop, you're integrating into an existing orchestration system (like LangGraph), or your use case doesn't benefit from agent autonomy.

The SDK is opinionated—it makes choices about tool execution, context management, and error handling. If you need custom logic there, the API gives you more control.

Getting started: Follow the quickstart on platform.claude.com. Define one simple agent, give it a task, observe how it reasons and uses tools.
