Phase 4 — Advanced Coding Agents

YOLO Mode & Sandboxing

Balance speed and safety: auto-approve safe commands, sandbox risky operations, and reduce approval friction without losing control.

The Permission Problem

Agentic tools default to "ask for permission" on every file edit and command. This is safe but slow. "Can I read main.py?" "Can I run npm test?" "Can I commit this change?" Hundreds of prompts per task.

The ideal: approve safe actions instantly, block dangerous ones, and focus only on approving risky decisions.

YOLO Mode (The Nuclear Option)

What it is: Skip all permission prompts. Claude Code runs with --dangerously-skip-permissions. No more "approve?" dialogs.

Speed: Orders of magnitude faster. Tasks run autonomously without interruption.

Risk: Extremely high. Claude can delete your entire codebase, push to production, expose secrets. One hallucination = disaster.

When to use: Only in isolated, sandboxed environments (CI pipelines, dev containers, ephemeral VMs). Never on your main machine or production access.

Claude Code Auto Mode (March 2026)

Anthropic released Auto Mode as a safer alternative to YOLO. It evaluates the risk of each action and auto-approves only safe operations.

How it works: A reasoning-blind classifier sits between Claude and every action. It sees the user message and raw tool call, but not Claude's reasoning. This prevents the agent from "talking" the classifier into bad decisions.

Results: In testing, auto-approval reduced permission prompts by up to 84% when combined with sandboxing.

Safe approvals: Reading files, running tests, linting, committing non-destructive changes.

Blocked actions: Deleting files, executing arbitrary shell commands, pushing to remote, modifying sensitive configs.

Command Whitelisting

Instead of blanket YOLO, whitelist specific safe commands. In your Claude Code config:

autoApproveCommands: [
"npm test",
"npm run lint",
"git status",
"git diff",
"node --version"
]

Claude can run these without asking. Any other command requires approval. This is a middle ground between YOLO (too loose) and asking for every permission (too strict).

Sandboxing Strategies

Docker containers: Run Claude Code in a container with mounted volumes. Network access is blocked by default. Claude can only read/write allowed directories.

Virtual machines: Spin up an ephemeral VM for CI jobs. Claude Code runs with YOLO mode. After the job, tear down the VM. No damage survives.

Dev containers: VS Code Dev Containers isolate the environment. Claude Code + sandboxing + auto-approval = safe, fast automation in development.

GitHub Actions / CI: Run Claude Code as a job. Grant only repo access (not production secrets). Let it run with auto-approval. Block any push to main; require PR review.

Layered Safety Configuration

Local development: Auto Mode enabled, sandboxing off, manual approval for deletions.

CI pipeline: Auto Mode + sandboxing, whitelisted commands, no manual approvals, PR-only output.

Production: Never run Claude Code with edit access. Use read-only mode or pre-approved scripts.

Secrets: Never store API keys, credentials, or tokens where Claude can access them. Use environment variables, secrets managers, or MCP with scoped credentials.

Setting Up Auto Mode + Sandboxing

In Claude Code:

autoMode: true — Enable auto-approval of safe actions.
sandboxedExecution: true — Restrict file/network access.
autoAllowBashIfSandboxed: true — Allow any bash command if sandboxed (filesystem isolation prevents damage).
allowedPaths: ["/workspace/src", "/workspace/tests"] — Restrict to these directories.

With these settings, Claude runs fast and safely. It can execute any bash command (because the sandbox blocks filesystem/network), but can't touch outside directories.

Monitoring & Rollback

Audit logging: Log every action Claude takes. Review logs after each task. Spot hallucinations early.

Git history: Each change is a commit. Use git log --oneline to see what changed. Revert bad commits with git reset.

Scheduled backups: If Claude has write access to important files, back them up before running automated tasks.

Tip: Start with manual approval on everything. As you gain confidence, enable Auto Mode. Graduate to sandboxing + YOLO only in CI. This gradual approach scales without disasters.
