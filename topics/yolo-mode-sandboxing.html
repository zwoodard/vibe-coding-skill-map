Phase 4 — Advanced Coding Agents

YOLO Mode & Sandboxing

Balance speed and safety: auto-approve safe commands, sandbox risky operations, and reduce approval friction without losing control.

The Permission Problem

Agentic tools default to "ask for permission" on every file edit and command. This is safe but slow. "Can I read main.py?" "Can I run npm test?" "Can I commit this change?" Hundreds of prompts per task.

The ideal: approve safe actions instantly, block dangerous ones, and focus only on approving risky decisions.

YOLO Mode (The Nuclear Option)

What it is: Skip all permission prompts. Claude Code runs with --dangerously-skip-permissions. No "approve?" dialogs.

Speed: Orders of magnitude faster. Tasks run autonomously without interruption.

Risk: Extremely high. Claude can delete files, push to production, expose secrets. One hallucination = disaster.

When to use: Only in isolated, sandboxed environments (CI pipelines, dev containers, ephemeral VMs). Never on your main machine with production access.

Claude Code Auto-Accept Mode

Anthropic's auto-accept mode is a safer alternative to YOLO. A reasoning-blind classifier evaluates each tool call and auto-approves only safe operations.

How it works: The classifier sees the user message and raw tool call, but not Claude's chain-of-thought reasoning. This prevents the agent from "persuading" the classifier into approving risky actions.

Safe approvals: Reading files, running tests, linting, non-destructive edits.

Blocked actions: Deleting files, arbitrary shell commands, pushing to remote, modifying sensitive configs.

Permission Allowlists

Instead of blanket YOLO, allowlist specific safe tools in settings.json:

{
"permissions": {
"allow": [
"Bash(npm test)",
"Bash(npm run lint)",
"Bash(git status)",
"Bash(git diff)",
"Read",
"Glob",
"Grep"
]
}
}

Claude can run allowlisted tools without asking. Everything else requires approval. This is the practical middle ground between YOLO (too loose) and approving every action (too slow).

Sandboxing Strategies

Docker containers: Run Claude Code in a container with mounted volumes. Network access is blocked by default. Claude can only read/write allowed directories.

Virtual machines: Spin up an ephemeral VM for CI jobs. Claude Code runs with YOLO mode. After the job, tear down the VM. No damage survives.

Dev containers: VS Code Dev Containers isolate the environment. Claude Code + sandboxing + auto-approval = safe, fast automation in development.

GitHub Actions / CI: Run Claude Code as a job. Grant only repo access (not production secrets). Let it run with auto-approval. Block any push to main; require PR review.

Layered Safety Configuration

Local development: Permission allowlists for safe tools, manual approval for deletions and shell commands.

CI pipeline: Container sandbox + --dangerously-skip-permissions, PR-only output, no manual approvals needed.

Production: Never run Claude Code with edit access. Use read-only mode or pre-approved scripts.

Secrets: Never store API keys, credentials, or tokens where Claude can access them. Use environment variables, secrets managers, or MCP with scoped credentials.

Combining Permissions + Sandboxing

In Claude Code settings.json:

Use "permissions": {"allow": [...]} to auto-approve specific tools. Combine with Docker or VM isolation so even allowlisted bash commands can't escape the sandbox.

In CI: Use --dangerously-skip-permissions inside a container with no network access and mounted volumes scoped to the workspace. The container is the safety net, not the permission system.

This layered approach — permission allowlists for convenience, container isolation for safety — gives you speed without risk.

Monitoring & Rollback

Audit logging: Log every action Claude takes. Review logs after each task. Spot hallucinations early.

Git history: Each change is a commit. Use git log --oneline to see what changed. Revert bad commits with git reset.

Scheduled backups: If Claude has write access to important files, back them up before running automated tasks.

Tip: Start with manual approval on everything. As you gain confidence, add permission allowlists for safe tools. Graduate to sandboxing + YOLO only in CI. This gradual approach scales without disasters.
