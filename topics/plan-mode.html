Phase 3 — Structured Workflows

Plan Mode

Review and approve AI plans before they execute code

What is Plan Mode?

Plan Mode is a checkpoint feature where AI agents analyze your codebase, think through an approach, and present a detailed plan before writing a single line of code. The AI reads files, understands the architecture, and tells you exactly what it intends to do—which files it will touch, the sequence of changes, and any assumptions it's making.

You review, edit, ask questions, or reject the plan entirely. Only after you approve does the AI proceed to implementation. It's "think before you build" made explicit and interactive.

Why Plan Mode Matters

Without a plan, you're delegating both strategy and execution to the AI. With a plan, you stay in control of strategy while the AI handles implementation. This dramatically reduces the risk of the AI going down a wrong path, misunderstanding your architecture, or creating unnecessary refactors.

Plan Mode catches misalignments early, before tokens are spent and code is written. It turns potential rework into a conversation.

Plan Mode Workflow

  1. You give a task: "Refactor the auth module to use JWT tokens."
  2. AI enters Plan Mode: It reads your current auth code, understands the existing structure, and analyzes dependencies.
  3. AI presents a plan: "I will: (1) Create a new JWT utility file, (2) Modify the login endpoint, (3) Update the middleware, (4) Add tests for token validation."
  4. You review & respond: "Good, but also handle token refresh. And use the existing secret manager, not a new one."
  5. AI revises the plan: Shows updated steps incorporating your feedback.
  6. You approve: "Looks good, execute."
  7. AI implements: Now it writes code, with the plan as a map.

This workflow is a design review before code review. Catch architecture mistakes in minutes, not after implementation.

Plan Mode Constraints

In Plan Mode, the AI is read-only. It can read files, search the codebase, and ask clarifying questions—but it cannot edit code, write files, or run shell commands. This keeps the mode lightweight and safe.

Some tools call this "analysis mode" or "thinking mode." The principle is the same: deliberate before acting.

When to Use Plan Mode

  • Large refactors: Restructuring modules, rearchitecting, touching multiple systems.
  • Unfamiliar codebases: Working in a project you don't know well yet.
  • Risky changes: Authentication, payment flows, data migrations.
  • Team decisions: When the direction affects other developers' work.

Skip Plan Mode for: Small bug fixes, obvious features, isolated changes in well-understood modules. The overhead isn't worth it for simple tasks.

Effective Plan Review

When the AI presents a plan, ask: Does this match my mental model? Are there dependencies I missed? Will this break anything downstream? Are there better approaches?

Don't just rubber-stamp—this is your chance to steer. If the plan is off, say so. Push back. The goal is alignment, not speed.

Combining with Markdown Specs

Pair Plan Mode with a detailed spec: "Here's what I want. AI, read the spec and the codebase, then show me your plan." The spec provides the what, the codebase provides the how, and the plan shows how the AI will bridge them.

This combo—specs + Plan Mode—gives you predictability and control.
