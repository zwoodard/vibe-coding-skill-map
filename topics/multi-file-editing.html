Phase 2 — AI-Assisted Coding

Multi-File Editing

Using AI to make coordinated changes across your entire codebase safely and efficiently

What Multi-File Editing Unlocks

Modern AI tools can now edit multiple files simultaneously to implement larger features. Tell AI: "Rename this function throughout the codebase" or "Add a new field to the User model, update the database schema, migrations, and API endpoints." AI handles the coordination automatically. This capability expanded from tools like Cursor (Composer mode) to GitHub Copilot and open-source tools like Cline and Aider. Multi-file refactoring consumes 25% of engineering time—$3.75M annually per 100-engineer team—because traditional tools analyze sequentially and miss cross-file dependencies.

Game changer: AI traces symbol definitions and usages across files using AST parsing, making large refactors safe and precise.

Use Cases: Renaming and Propagation

Renaming a function: "Rename fetchUserData to getUserData throughout the codebase." AI finds all imports, calls, exports, and tests. Updates them everywhere without touching strings or comments that happen to contain the old name.

Extracting constants: "Create a constant MAX_RETRIES = 3, replace all instances of hardcoded 3 in retry logic."

Removing a parameter: "Remove the deprecated callback parameter from sendEmail(). Update all call sites."

These changes might span 10-50 files. AI maintains consistency that's tedious to verify manually.

Model and View Coordination

Adding a field to a model: "Add a lastLogin field to the User model. Create a database migration. Update the API serializer. Add tests." AI: creates the field in the model, writes a migration file, updates the JSON response schema, adds test fixtures, and updates documentation comments.

Restructuring imports: "Move UserService from util/auth to services/user. Update all imports." AI finds every file importing the old location and updates them.

Architecture shifts: "Convert this MVC app to a modular structure where each feature is a self-contained folder." AI reorganizes files, updates paths, and regenerates export/import chains.

Key insight: AI parses ASTs to understand code structure deeply, not just regex find-replace. It won't break syntax or logic.

Scoping Requests Clearly

Large changes need clear boundaries. Be specific: "Rename only the Controller class, not controller-related strings." "Update the Orders module, not Customers." "Change Person.age to Person.birthDate in models/ only, leave schemas/ unchanged for now."

Ask AI to confirm scope before executing: "Here's what I'll change: [list files]. Should I proceed?" Review the list before saying yes.

  • Name the exact files or directories affected
  • List what should NOT change if it's ambiguous
  • Specify which frameworks/languages if the codebase mixes them
  • Ask for a summary of planned changes before execution

Reviewing Diffs Carefully

Always review diffs before merging. AI makes mistakes: wrong variable references, incomplete updates, or changes in unintended files. Use your IDE's diff viewer to check each file. Look for: imports that got deleted, type mismatches, inconsistent naming, or business logic changes.

Example: "Rename userId to id" might accidentally change user_id in database column names, breaking queries. Good diffs catch this. Always review.

Safety practice: Make AI changes in a feature branch. Review diffs, run tests, then merge. Never merge large refactors directly to main.

Context Window Limitations

A critical challenge: AI tools have fixed context windows (token limits). When refactoring 50 files totaling 200,000 tokens but context holds only 100,000 tokens, the tool can't maintain consistent state across all files. It might update the first 30 files correctly but miss later ones.

Solution: Break large refactors into smaller steps. Instead of "Rename X throughout the codebase," do it module-by-module: "Rename X in the auth module," then "Rename X in the API module." More requests, but better consistency.

Incremental Commits

For large multi-file changes, commit incrementally. After AI makes changes, run tests, review, and commit before requesting the next change. This approach: catches errors early, makes diffs reviewable, enables rollback of specific parts, and documents what changed and why.

  • Request one logical change at a time
  • Run tests after each change
  • Commit with a clear message: "Rename fetchUser to getUser across auth module"
  • Move to the next refactor step

Tools for Multi-File Editing

Cursor's Composer Mode: Press Cmd+Shift+I, describe a complex task, AI edits multiple files and shows a preview. GitHub Copilot: Added multi-file editing capability; works within pull requests. Cline (open-source): Agentic workflow for large refactors. Google Gemini Code Assist: Recognized as best for very large codebases.

When to Avoid Multi-File Editing

  • Production systems with high stakes: Use if changes are non-critical or well-tested, otherwise do manually
  • Ambiguous requirements: "Make this better" is too vague. Humans make the call
  • Performance-critical paths: Humans should optimize hot paths, not AI
  • Business logic changes: Financial calculations, user permissions, or compliance rules should be reviewed by domain experts
