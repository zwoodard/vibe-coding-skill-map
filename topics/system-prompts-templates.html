System Prompts & Templates

Define AI behavior, tone, and constraints upfront

What is a System Prompt?

A system prompt is a set of instructions given to an AI model before user interaction begins. It defines the model's role, personality, constraints, and how it should behave throughout the conversation. Unlike user prompts (your requests), system prompts are persistent—they apply to every interaction in that session.

Think of a system prompt as the AI's operating manual. It says "You are a code reviewer" or "You are a technical writer" and sets the tone for everything that follows.

Key Components of Good System Prompts

  • Role: "You are a senior backend engineer" or "You are a security auditor."
  • Context: What domain are you operating in? What's important about this project?
  • Constraints: What should you NOT do? "Don't suggest deprecated libraries." "Don't write code longer than 50 lines."
  • Format: How should responses be structured? "Always respond with: (1) explanation, (2) code, (3) gotcha."
  • Tone: Professional, casual, concise, verbose? "Be direct and precise. Avoid fluff."
  • Scope: What are your boundaries? "You can suggest architecture but not make executive decisions."

Example System Prompts

For a Code Reviewer:

You are a senior code reviewer. Review code for correctness, performance, and maintainability. Always flag: deprecated patterns, missing error handling, and security issues. Format: (1) Summary, (2) Issues with severity, (3) Suggestions.

For API Documentation:

You write API documentation. Be precise and concise. Always include: endpoint, method, parameters, response format, error codes, example. Use markdown. Assume the reader is a developer, not a novice.

System prompts work best at 100-500 words. More than that, and you're wasting tokens. Less, and you're under-specifying behavior.

Constraints Are Powerful

Constraints prevent AI from going off-rails. Without them, you get whatever the model decides. With them, you get consistency.

Examples: "Do not suggest Docker unless asked." "Always validate input." "Never hardcode secrets." "If unsure, ask for clarification rather than guessing."

The more explicit your constraints, the more predictable the AI's behavior.

Reusable Prompt Templates

Create a library of system prompts for common tasks: code generation, reviewing, documenting, refactoring, testing. Store them as Markdown files in your project:

docs/prompts/code-reviewer.md
docs/prompts/api-documenter.md
docs/prompts/test-writer.md

Version control these prompts alongside your code. When you improve a prompt, commit it. When you need that prompt later, you have the version that worked.

Version-Controlling Prompts

Treat system prompts like code. Keep them in Git. When a prompt produces great results, you want that version forever. When you refine it, you want to see the diff.

Example git log for a prompt:

commit abc123: "Simplify code reviewer prompt, remove redundancy"
commit def456: "Add constraint about avoiding deprecated patterns"

This history becomes institutional knowledge about what works in your team.

Testing & Refining Prompts

A good prompt improves output consistency. Test by running the same task with the same prompt multiple times. Does the output vary wildly? The prompt needs refinement. Is it consistent? You're winning.

When output is bad, it's often not the prompt—it's the task being too vague or the AI misunderstanding the context. Refine the prompt, add constraints, provide examples.
