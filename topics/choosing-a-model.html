Choosing a Model

Overview of the AI landscape and what each model family does best.

The Major Providers

Model versions change every few months. These are the families to know—check each provider's docs for the latest version numbers.

Claude (Anthropic): Strongest at writing, analysis, and step-by-step reasoning. The Sonnet tier offers near-Opus quality at lower cost. Excellent for long-form tasks and complex problem-solving.

GPT / o-series (OpenAI): Strong at tool integration, coding, and factual precision. The o-series models (o1, o3) add dedicated reasoning capabilities. Wide ecosystem and API support.

Gemini (Google): Competitive pricing and strong at multi-modal tasks (images, video, documents). Deep integration with Google services. Good value for reasoning-heavy work.

Llama (Meta): Open-weight, can run locally. Great for privacy-sensitive work, cost-conscious teams, or customization. Increasingly competitive with closed-source models.

Extended Thinking vs. Fast Inference

Extended Thinking models (Claude with extended thinking, OpenAI's o-series) work step-by-step internally before answering. They're slower but better at:

  • Debugging complex logic and code
  • System design and architecture
  • Math and multi-step reasoning
  • Tasks where "thinking through it" matters

Fast models (Claude Sonnet, GPT-4o, Gemini Flash) respond quickly. Best for:

  • Code generation and refactoring
  • Writing and documentation
  • Brainstorming and ideation
  • Real-time interactions and agents

Use extended thinking when the problem is hard. Use fast models when speed or cost matters more than perfection.

Large vs. Small: The Tradeoff

Frontier models (Claude Opus, OpenAI's latest GPT/o-series, Gemini Ultra/Pro):

  • Highest quality, best reasoning, most reliable
  • Higher cost (check current pricing—it drops frequently)
  • Slower inference
  • Best for critical, complex tasks

Mid-tier models (Claude Sonnet, GPT-4o, Gemini Pro):

  • Good quality, 80%+ of frontier performance on most tasks
  • Significantly cheaper than frontier
  • Fast and reliable for daily development work
  • Sweet spot for teams and solo builders

Smaller models (Claude Haiku, Gemini Flash, Llama):

  • Cheap, fast, can run locally
  • Best for simple tasks, high-volume work, embedding in apps
  • Weaker at reasoning and subtle tasks

Cost Reality

Pricing changes frequently and trends downward. The pattern to understand:

  • Output tokens cost more than input tokens (generation is more compute-intensive than reading)
  • Thinking/reasoning tokens add cost on top of output tokens
  • Smaller models are 5–20x cheaper than frontier models for the same task

For a typical development session (20 questions, moderate responses), expect to spend well under $1 on any mid-tier model. Cost is rarely the blocker—a bad model choice wastes more time than the difference in API cost.

Check each provider's pricing page directly. Prices drop regularly, and cached/batched API calls are often discounted.

The Context Window Tie

All major frontier models now offer 128K–1M+ token context windows. For most development work, context length is no longer a deciding factor. You can paste large codebases, documentation, and logs in one prompt.

Don't choose based on context window anymore. Pick the model that thinks best for your task.

Quick Decision Tree

  • Debugging or system design? → Any frontier model with extended thinking / reasoning mode
  • Writing, refactoring, daily coding? → Mid-tier model (Claude Sonnet, GPT-4o, Gemini Pro)
  • Building agents or software automation? → Frontier model with strong tool-use support
  • Reasoning-heavy work on a budget? → Compare current pricing; Gemini is often cheapest
  • Privacy or local deployment? → Llama or similar open-weight models
  • Quick, cheap tasks (summaries, simple code)? → Small/fast models (Haiku, Flash, etc.)

Pro Tips

  • Start with a mid-tier model (Claude Sonnet, GPT-4o). Upgrade only if results disappoint.
  • Try different models on the same task. You'll notice patterns in what each does best.
  • Check model release notes regularly. Knowledge cutoffs and capabilities change with each release.
  • Use cheaper models for iteration, frontier models for final polish.
