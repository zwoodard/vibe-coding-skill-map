Phase 2 — AI-Assisted Coding

Chat-Based Coding

Using conversational AI to write, explain, and refactor code in real-time

Sidebar Chat in Your Editor

Modern AI code editors like Cursor and VS Code with Copilot feature integrated chat panels. Open a chat window while coding to ask questions without switching applications. Select code and mention it in chat using @symbol references to give context. Use Cmd+K (Ctrl+K on Windows) to open inline editing, then describe a change to apply it directly to highlighted code.

Pro tip: Keep your chat history within a single session—AI understands previous questions and code context, making follow-ups more accurate.

Generating Functions from Descriptions

Describe what you want a function to do in plain English, and AI generates working code. Example: "Create a function that validates email addresses using regex and returns true if valid, false otherwise." AI produces the implementation with error handling. Be specific about inputs, outputs, and edge cases for better results. Specify language, framework preferences, and desired style (async/sync, class-based/functional).

  • Describe intent clearly and concisely
  • Mention expected inputs and return types
  • Note any edge cases to handle
  • Review generated code before committing

Explaining Unfamiliar Code

Paste code into chat and ask "What does this do?" or select it and use the inline explain feature. AI breaks down complex logic, explains library calls, and clarifies why decisions were made. Particularly useful for understanding legacy code, third-party libraries, or patterns you haven't seen. Ask follow-up questions: "Why use async here?" or "What's this decorator doing?"

Refactoring with AI

Ask AI to improve code quality without changing behavior. Examples: "Make this more readable," "Optimize this database query," "Add proper error handling," or "Extract this into a helper function." AI maintains functionality while improving performance, readability, or security. Always review diffs—AI sometimes introduces subtle changes.

Best practice: Request one type of change at a time. "Improve performance" is too broad; try "Cache this API response" or "Use batch operations here."

Debugging by Pasting Errors

Paste error messages, stack traces, or weird behavior descriptions into chat. AI identifies likely causes and suggests fixes. "TypeError: Cannot read property 'map' of undefined" becomes actionable guidance: add null checks, verify API response shape, or adjust initialization order. Include context: what action triggered the error? What did you expect?

  • Paste full stack traces, not just the headline
  • Describe steps to reproduce the issue
  • Share relevant code sections
  • Mention what you've already tried

Crafting Better Prompts

Vague: "Make this code better." Clear: "Refactor this React component to use hooks instead of class syntax, keeping the same behavior." Specific prompts yield better code. Include context about constraints: "This needs to work in Node.js 18+" or "Must be database-agnostic." State your goal, not just what you want done.

Use examples when helpful: "Format the output like this: {'status': 'success', 'data': [...]}." Reference exact line numbers or function names. Say "this fetchUser function" instead of "this function."

Common Pitfalls

  • Over-trusting generated code: Always review for security, performance, and correctness before merging
  • Insufficient context: AI can't guess your architecture or business rules—spell them out
  • Asking for multiple changes at once: Split requests so AI focuses on one task
  • Ignoring warnings: If AI says "this might break X," investigate before deploying
