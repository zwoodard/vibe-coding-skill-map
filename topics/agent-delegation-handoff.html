Phase 6 — Sub-Agents & Orchestration

Agent Delegation & Handoff

Master patterns for spawning sub-agents, passing context, collecting results, and gracefully handling failures.

Spawning Sub-Agents

A parent agent spawns child agents to handle specific work. For example, a coordinator asks a researcher agent to "find information about Python async patterns." The parent provides the task and context, the child executes independently, and returns results.

Spawning means: create a new agent instance with its own system prompt, tools, and memory space. The child agent doesn't see the parent's full context (keeping things focused). Instead, it receives a task description and any background information needed. When done, it returns structured output (results, status, errors).

Passing Context Between Agents

Context passing is critical. A child agent needs enough information to complete its task but not so much that context bloat becomes expensive. Best practices:

  • Explicit task: "Analyze this code for performance issues" is better than passing the entire codebase.
  • Relevant files only: Include specific files or excerpts, not everything.
  • Shared memory: Use a shared knowledge base or memory store that agents can read/write. A researcher stores findings in shared memory; the coordinator later reads those findings.
  • Session ID: Pass a session identifier so child agents can access prior work from the same task run.

Avoid passing the full parent context to each child—this defeats the purpose of parallelization and wastes tokens.

Collecting Results

When a child agent finishes, the parent must collect and validate its output. Standardize result formats (JSON with fields like status, result, errors, metadata). The parent then:

  • Checks if the result is valid (expected structure, non-empty data).
  • Decides whether to accept, retry, or escalate the task.
  • Aggregates results from multiple children into a coherent answer.
  • Handles partial failures (one agent succeeded, another didn't).

For example, if a code generator produces code but tests fail, the parent might send the failures back to the generator to fix, rather than accepting broken code.

Failure Recovery & Retry Logic

Sub-agents can fail: timeouts, invalid tool calls, tool execution errors. The parent should implement retry logic: If a tool call fails transiently (network error), retry with exponential backoff. If it fails permanently (invalid parameters), return an error to the parent and don't retry. For partial failures (3 of 5 agents succeeded), aggregate successful results and escalate the failures.

Set timeouts on sub-agent execution. If an agent hangs, timeout and reassign the task. Log all failures for debugging. Don't propagate errors silently—surface them so the parent can decide how to handle them.

The Microservices Analogy

Think of agents like microservices. A service is a focused unit that does one thing well (user service, payment service, inventory service). Microservices communicate via APIs, have isolated data stores, and can fail independently. The same applies to agents.

Each agent is a "service" with a specific job. They communicate via structured messages (tool calls, memory). A failure in one agent doesn't take down the whole system—other agents can continue working. Use this analogy to design your agent system: loose coupling, clear contracts (tool schemas), and graceful degradation on failure.

Practical Workflow

1. Parent receives task: "Build and test a feature." 2. Parent spawns coder agent with the spec and passes relevant context. 3. Coder returns code. 4. Parent spawns test agent, passes code, and test spec. 5. Test agent runs tests and returns pass/fail. 6. If tests fail, parent sends failures back to coder for fixes. 7. If tests pass, parent returns success to user.

Throughout, parent logs every spawn, result, and decision. This audit trail is invaluable for debugging and understanding what happened.

Pro tip: Use structured logging with timestamps, agent IDs, and task IDs. You'll thank yourself when debugging production issues.
