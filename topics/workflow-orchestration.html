Phase 6 — Sub-Agents & Orchestration

Workflow Orchestration

Design complex, multi-step AI workflows with branching, parallelization, error recovery, and human checkpoints.

DAG-Based Workflows

A workflow is a directed acyclic graph (DAG) of tasks. Each node represents a step (run a model, call an API, execute code). Edges represent dependencies (Task B waits for Task A's output). A DAG ensures no circular loops and lets you see the full workflow structure upfront.

Example workflow: Parse document → Extract entities → Summarize → Quality check → Deliver results. Parse has no dependencies. Extract depends on Parse. Summarize depends on Extract. Quality check depends on Summarize. Each step is a node; dependencies are edges.

Sequential vs. Parallel Execution

Sequential: One task runs, then the next. Good when each step depends on the previous output. Slower but simple. Parallel: Multiple independent tasks run simultaneously. Good when tasks don't depend on each other. Faster but requires result aggregation.

In the example above, Parse must be sequential (foundational). Then Extract and Summarize could theoretically run parallel (if Extract feeds to Summarize through a shared memory store). Quality check must follow Summarize. The orchestrator determines the optimal execution path based on the DAG structure.

Conditional Branching

Workflows often need conditional logic: "If extraction succeeded, continue. If extraction failed, send to manual review." Use branching to split the workflow based on task results.

  • If/else: "If high confidence, auto-approve. Else, escalate to human."
  • Switch: "If document type is contract, use legal reviewer. If invoice, use accounting reviewer."
  • Loop: "Retry extraction up to 3 times. If still failing, escalate."

Each branch is a sub-DAG. The orchestrator navigates the branches based on runtime decisions. This creates adaptive workflows that respond to intermediate results.

Human-in-the-Loop Checkpoints

Not all decisions should be automated. Insert human checkpoints at critical decision points. A workflow might auto-process low-risk documents but flag high-uncertainty results for human review. The checkpoint pauses the workflow, notifies a human, and resumes when they approve/reject.

Implement checkpoints by storing workflow state, queuing the decision request to a task system (e.g., a human task queue), and resuming when a human provides input. This keeps workflows from going off the rails on edge cases while automating routine work.

Retry Logic & Error Handling

Tasks fail. Implement exponential backoff: retry immediately, then after 1 second, then 2, then 4. Set max retries (usually 3-5). For transient errors (network hiccup), retry. For permanent errors (invalid input), escalate instead of retrying endlessly.

At each error, the orchestrator decides: retry with the same parameters, retry with different parameters, skip this task and move to the next, or escalate to a human. Log all failures with timestamps and context so you can debug issues later. Set timeouts on each task—if a task hangs for 5 minutes, cancel it and move on.

Tools & Platforms

Several platforms handle workflow orchestration: Apache Airflow is open-source and widely used for data pipelines and AI workflows. Define DAGs in Python, schedule runs, monitor execution. Temporal specializes in long-running, fault-tolerant workflows; popular in microservices. AWS Step Functions is a serverless orchestration service. Strands Agents integrates AI and workflow logic with advanced branching.

For simpler use cases, the Claude Agent SDK's built-in orchestration may suffice. For complex, multi-step enterprise workflows, use a dedicated platform like Airflow or Temporal.

Practical Example: Document Processing

1. Ingest document. 2. Parse (extract text). 3. If parse fails, escalate to manual review. 4. If parse succeeds, extract entities in parallel (NER agent, metadata extractor, summary agent). 5. Aggregate results. 6. Quality check: is confidence high? If yes, deliver. If no, flag for human review. 7. Log outcome for analytics.

This workflow has sequential steps (ingest, parse), parallel steps (extract agents), branching (on parse success), checkpoints (quality check), and error handling (manual review path).

Best practice: Start simple. Define the happy path first, then add branches and error handling incrementally.
