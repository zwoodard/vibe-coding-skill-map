Skills & Custom Commands

Extend Claude Code with skills and custom slash commands to package repeatable workflows and share them across your team.

Slash Commands vs. Skills

Slash commands are fixed, hardcoded operations built into Claude Code. Examples: /clear (clear context), /help (show docs), /model (switch models), /cost (show API costs).

Skills are prompt-based, discoverable capabilities. When invoked (by you or by Claude), they load instructions and supporting files into context. Skills can be auto-invoked by the agent when they detect they're relevant.

Custom Slash Commands

Create in: ~/.claude/commands/ (global) or project/.claude/commands/ (local).

File format: command-name.md (must be kebab-case).

Content: Plain markdown with natural-language instructions. Use $ARGUMENTS placeholder for user input.

Example: lint-fix.md contains "Run eslint on the codebase and auto-fix violations. Arguments: $ARGUMENTS (optional file glob)."

Invoke with: /lint-fix src/**/*.js

Limitation: Slash commands don't invoke Claude directly; they're just shortcuts. Skills are more flexible.

Creating Skills

Anatomy: Each skill is a directory with a SKILL.md file.

Structure:

my-skill/
├── SKILL.md (required)
├── script.sh or .js (optional)
└── config.json (optional)

SKILL.md format: YAML frontmatter (between ---) + markdown instructions.

Frontmatter fields:

  • name: Display name
  • description: One-line summary
  • triggers: When Claude should auto-invoke (e.g., ["test failure", "build error"])
  • tags: Categorize the skill (e.g., ["testing", "ci"])

Example: Build & Test Skill

Location: project/.claude/skills/build-and-test/SKILL.md

---
name: Build & Test
description: Run npm build, then tests, then report results
triggers: ["npm error", "test failure"]
tags: ["build", "ci"]
---

Run npm run build. If it fails, stop and report the error.
If build succeeds, run npm test.
Report pass/fail and commit-ready status.

Claude auto-triggers this skill when it detects a build error. You can also invoke it manually: /build-and-test (Claude discovers it and runs it).

Sharing Skills Across Teams

Git repository: Store skills in a shared repo. Teams clone it and copy the .claude/skills directory locally.

NPM package: Package skills as an npm module. Teams install with npm install @company/claude-skills and symlink into .claude.

Global registry: Publish to GitHub or a skills registry. List with /skills and install with /skill install owner/repo.

Documentation: Include a README in each skill directory explaining when to use it, what it does, and any prerequisites.

Built-In Skills & Commands (Quick Reference)

/skills — List all available skills (built-in + custom).

/clear — Clear context and conversation history.

/model — Switch AI models (Claude 3.5 Sonnet, etc.).

/cost — Show API costs and token usage.

/help — Show documentation and usage.

/compact — Compress context to fit larger files.

Tip: Start with one repeatable task you do every week (e.g., running tests, formatting code, generating docs). Turn it into a skill. Use it twice. Then share it with your team. Multiply by 5–10 skills, and you've automated hours of work.
