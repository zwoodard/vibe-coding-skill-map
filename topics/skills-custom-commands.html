Skills & Custom Commands

Extend Claude Code with skills and custom slash commands to package repeatable workflows and share them across your team.

Custom Slash Commands vs. Skills

Custom slash commands are markdown files that inject a prompt when you type /command-name. They're simple prompt templates — quick to create, easy to share.

Skills are richer: markdown files with YAML frontmatter that Claude can auto-discover and invoke when relevant. Skills load instructions into context and guide Claude's behavior for specific task types.

Both live under .claude/commands/. The difference is that skills have frontmatter with name and description fields, enabling auto-invocation.

Creating Custom Slash Commands

Location: ~/.claude/commands/ (global) or .claude/commands/ (project-local).

File format: command-name.md — the filename becomes the slash command name.

Content: Plain markdown with natural-language instructions. Use $ARGUMENTS placeholder for user input.

Example: .claude/commands/lint-fix.md:

Run eslint on the following files and auto-fix all violations: $ARGUMENTS

Invoke with: /project:lint-fix src/**/*.js

Creating Skills

Anatomy: A skill is a .md file with YAML frontmatter.

Frontmatter fields:

  • name: Display name (required)
  • description: One-line summary — this is what Claude reads to decide when to auto-invoke the skill (required)

Body: Markdown instructions that get loaded into context when the skill is invoked.

Write the description carefully — it's the trigger. Claude matches it against the current task to decide relevance.

Example: Build & Test Skill

Location: .claude/commands/build-and-test.md

---
name: build-and-test
description: Use when build errors or test failures occur to run the full build-then-test cycle
---

Run npm run build. If it fails, stop and report the error.
If build succeeds, run npm test.
Report pass/fail and whether the code is commit-ready.

Claude can auto-invoke this when it encounters build errors. You can also trigger it manually: /project:build-and-test.

Sharing Commands & Skills Across Teams

Project-local: Commit .claude/commands/ to your repo. Every team member gets the same skills when they clone.

Plugins: Package commands, skills, hooks, and agents into a Claude Code plugin with a plugin.json manifest. Plugins are installable and versioned.

Global commands: Place personal commands in ~/.claude/commands/ for use across all projects.

Built-In Commands (Quick Reference)

/help — Show documentation and available commands.

/clear — Clear conversation history and context.

/model — Switch AI models (Opus, Sonnet, Haiku).

/cost — Show token usage and API costs.

/compact — Compress context to fit more content.

Tip: Start with one repeatable task you do every week (e.g., running tests, formatting code, generating docs). Turn it into a skill. Use it twice. Then share it with your team. Multiply by 5–10 skills, and you've automated hours of work.
