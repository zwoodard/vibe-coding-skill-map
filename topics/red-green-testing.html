Red-Green Testing with AI

Test-driven development that puts you in control of AI-generated code

TDD & the Red-Green-Refactor Cycle

Red: Write a test for a feature that doesn't exist yet. The test fails (you see red).

Green: Write the minimum code needed to make the test pass (you see green).

Refactor: Clean up the code while keeping tests passing. No new features, just better design.

This cycle inverts traditional development: tests come first, code follows. The tests define what "done" means before you write a line of implementation.

Why TDD + AI is Powerful

Test-first development is a natural fit for AI code generation because it answers the AI's biggest question: "How do I know when I'm done?" Tests provide an unambiguous definition of correctness.

Without tests, the AI guesses at requirements and might add features you didn't ask for. With tests, the AI has a clear success criterion: make the tests pass, no more, no less.

The AI-Assisted Red-Green Cycle

  1. You write the test: "Given a user with a valid token, they can access the dashboard."
  2. Test fails (Red): You run it, it fails. Good—that's expected.
  3. AI implements code: You give the AI the test and say "Make this pass. Nothing more."
  4. Test passes (Green): The AI writes code. You run tests. They pass.
  5. You review the implementation: Is it correct? Is it clean? If not, ask for refactoring.
  6. Refactor (together): You and AI clean up the code, keeping tests green.

The AI can generate boilerplate and edge cases instantly, turning TDD's biggest weakness (manual test writing) into an accelerator. You define intent, AI implements it.

Writing Tests First

Before you ask the AI to implement, write the tests yourself. Be specific about inputs, outputs, and edge cases. Tests are your spec—they should be clear enough that an AI (or a new teammate) can implement from them alone.

Example good test spec:

describe('loginUser', () => {
  it('returns a JWT token for valid credentials', () => { ... })
  it('throws 401 for invalid password', () => { ... })
  it('throws 404 for nonexistent user', () => { ... })
})

Tests as Guard Rails

A robust test suite acts as guard rails for AI-generated code. The AI can't veer off course without failing tests. This is enormous: you get AI speed without AI surprises.

The better your tests, the more you trust the AI's output. Invest in testing early.

AI Can Write Tests Too

Once you've written a few tests, you can ask the AI to write more. Give it the pattern and ask for edge cases: "Write tests for invalid inputs, boundary conditions, and error states."

The AI will generate a comprehensive test suite in seconds. You review, adjust, and use it. This turns testing from a bottleneck into a rapid-iteration tool.

Continuous Testing in the Cycle

As you iterate with AI, run tests constantly. After each implementation, run npm test or equivalent. Tests failing? Push back to the AI with the failure output. Tests passing? Ask for refactoring or move to the next feature.

This tight feedback loop keeps both you and the AI honest.

Regression Prevention

A test suite grows with your codebase. Every feature gets tests. Every bug fix includes a regression test (a test for the bug you just fixed). Over time, your test suite protects against future mistakes—especially important when using AI across many features.

Think of tests as insurance against AI drift. The larger your test suite, the safer your AI-assisted development.
