Phase 4 — Advanced Coding Agents

Terminal-Based Agents

Mastering AI workflows in the shell: command piping, autonomous iteration, and when CLI agents outshine IDEs.

Why Terminal Agents Matter

Terminal agents fit naturally into Unix philosophy: take input, process, produce output. AI agents break down problems, run commands, check results, and iterate. This feedback loop aligns perfectly with shell workflows.

  • Easy multi-session: Open multiple terminal tabs or tmux panes, each running its own agent on a different task. Multi-session parallelism is trivially easy compared to IDE-based agents where you're locked to one workspace.
  • CI/CD ready: Agents run in pipelines, serverless, cron jobs
  • Lightweight: CLI tools run on any machine with Node/Python
  • Reproducibility: Shell history, scripts, and piping create auditable records

Core Workflows

Piping command output to AI: Pipe grep results, logs, or build errors directly to Claude Code or Aider. The agent reads the output and diagnoses issues or generates fixes.

Autonomous iterations: Agent runs a command, sees the error, tweaks code, re-runs, repeats until success. You approve the final result.

Multi-step reasoning: Describe a goal (e.g., "refactor this module to async/await"). The agent plans steps, executes them, checks for lint errors or test failures, and self-corrects.

Embedded in scripts: Call Claude Code or Aider from bash/Python scripts for hands-free automation. Pass stdin, parse JSON output, chain operations.

Claude Code CLI Essentials

claude -p "refactor main.py to use async/await" — Non-interactive (print) mode for scripting.

git diff | claude -p "review these changes" — Pipe command output for analysis.

claude — Interactive mode with full tool use (file editing, shell commands, git).

Use permission allowlists in settings.json to auto-approve safe commands. Use --dangerously-skip-permissions only in sandboxed environments (see YOLO Mode & Sandboxing).

GitHub Copilot CLI

Copilot CLI (GA February 2026) is GitHub's terminal-native coding agent. It plans multi-step tasks, edits files, runs tests, and iterates autonomously.

Autopilot mode: Works end-to-end without stopping for approval at each step — comparable to Claude Code's YOLO mode.

Fleet mode (/fleet): Breaks a task into subtasks and spins up parallel subagents to execute them concurrently. Built-in orchestration for parallel work.

Specialized agents: Automatically delegates to purpose-built agents (Explore, Task, Code Review, Plan) depending on the prompt.

Background delegation: Prefix a prompt with & to hand work off to a cloud-based coding agent, freeing your terminal.

If your team is already in the GitHub ecosystem, Copilot CLI is a strong option. It supports multiple models (Anthropic, OpenAI, Google) and maintains cross-session memory.

Terminal vs. IDE Agents

Terminal wins: Refactoring, git workflows, multi-repo tasks, CI/CD, scripting, cost efficiency (pay per query, not monthly seat).

IDE wins: Visual debugging, UI-heavy projects, inline suggestions, file tree navigation, real-time linting.

Hybrid approach: Use Claude Code terminal for backend/refactoring; use Cursor or Cline for frontend/UI.

Working Outside the IDE

Doing most of your development in a terminal instead of an IDE feels strange at first — especially if you've spent years in VS Code or JetBrains. But modern terminal agents like Claude Code have largely replaced the need for an IDE in many workflows. They read and navigate your codebase, make multi-file edits, run tests, handle git, and iterate on errors — all things you used to need an IDE for.

Once you've spent a week or two working this way, it stops feeling like a limitation and starts feeling like less overhead. You're not fighting a UI or waiting for an extension to index. You're just describing what you want and watching it happen.

This doesn't mean you should never open an IDE — visual debugging, UI work, and complex diff review are still easier with a GUI. But for the bulk of backend development, refactoring, and automation, the terminal is increasingly where the work gets done.

Planning Styles in Terminal Agents

Reason-and-act (Gemini CLI): Exploratory; solves one step at a time. Fast feedback, best for debugging.

Plan-and-execute (Claude Code): Thinks through the problem before acting. Best for complex multi-step tasks.

Structured output (Codex CLI): Machine-readable JSON output mode. Ideal for scripted, deterministic workflows integrated into larger pipelines.

Tip: Scope work carefully. Use CLAUDE.md or AGENTS.md context files to tell the agent what files are safe to touch, coding conventions, and project constraints. Combine with sandboxing for safe auto-approval in CI.
