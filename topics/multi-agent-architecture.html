Phase 6 — Sub-Agents & Orchestration

Multi-Agent Architecture

Design systems where specialized AI agents collaborate, divide labor, and solve complex problems together.

What Is Multi-Agent?

A multi-agent system consists of multiple AI agents, each with specialized skills or knowledge, working together toward a common goal. Rather than a single monolithic model trying to handle everything, you create focused agents: a planner that decomposes tasks, domain experts (code generator, researcher, reviewer), and a coordinator that aggregates results.

This mirrors how human teams solve complex problems. One person doesn't code, test, document, and deploy alone. Teams specialize. Multi-agent systems scale reasoning by parallelizing work and reducing individual context burden.

Agent Roles & Specialization

Define each agent's purpose clearly. Common roles in a software engineering context:

  • Planner: Receives the user's goal, breaks it into sub-tasks, delegates to specialists.
  • Researcher: Gathers information from docs, databases, web searches; summarizes findings.
  • Code Generator: Writes implementation, tests, and deployment scripts based on requirements.
  • Reviewer: Audits code for bugs, security, style; suggests improvements or requests rework.
  • Executor: Runs tests, deploys, monitors; reports status back to the planner.

Each agent has its own system prompt tuned to its role, restricted tool access (a reviewer doesn't need deployment tools), and specialized knowledge context. This isolation prevents hallucination and keeps context windows efficient.

Task Delegation & Flow

The planner agent examines the user's request, decides what needs to happen, and creates sub-tasks for specialists. For example: "Build a REST API endpoint." The planner breaks this into: (1) Design the schema (researcher), (2) Generate code (coder), (3) Write tests (test agent), (4) Review (reviewer), (5) Deploy (executor).

Delegation can be sequential (one task at a time, waiting for results) or parallel (multiple agents work simultaneously on independent tasks). Parallel is faster but requires careful result aggregation. Use sequential for dependent tasks (can't code before design is done) and parallel for independent work.

Result Aggregation

When specialists finish, the coordinator collects their outputs and synthesizes a final answer. A code agent produces implementation; a test agent produces test results; a reviewer produces feedback. The coordinator combines these: "Here's the code. Tests pass (report). Reviewer approved (report). Ready to deploy."

Aggregation logic decides whether to accept, retry, or escalate. If the reviewer finds critical issues, loop back to the coder. If test coverage is low, request additional tests. The coordinator is responsible for quality gates and decision logic.

Communication Patterns

Agents communicate via structured messages or shared memory. In a hierarchical system, all communication flows through the coordinator (simpler, slower). In a blackboard architecture, agents read/write to a shared workspace (faster, requires synchronization). Direct agent-to-agent communication (peer-to-peer) is also possible but can create bottlenecks.

Key principle: Make communication explicit and auditable. Log every message, delegate decision, and result. Use structured formats (JSON, not free text) so results are machine-readable and can be validated.

Real Examples

Customer Support: Classifier agent routes issues (billing, technical, account). Specialists handle each type. Summary agent creates a ticket. Document Processing: Extractor agent reads documents, NER agent identifies entities, summarizer agent writes summaries, QA agent checks quality. Software Audit: Scanner agent finds issues, analyst agents investigate by domain (security, performance, code quality), report agent synthesizes findings.

Best practice: Start with a simple coordinator + 2-3 specialists. Validate that this structure solves your problem before adding complexity.
